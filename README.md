# PulseBreath — integrated Windows + Android prototype

This project separates a **shared Java math/data layer** (`:core`) from two platform adapters:
- `:desktop` — JavaFX Windows app, SQLite JDBC, Wi-Fi HTTP polling, BLE via the included Python/bleak bridge.
- `:androidApp` — native Android app, Android BLE GATT, Wi-Fi NetworkSpecifier (Android 10+), Android SQLite.

The shared `MathProcessor` source came from the provided `SignalProcessor.java`; it is renamed to `MathProcessor.java` and placed in `com.pulsbreath.core`. Both apps use `MeasurementPipeline` and `SensorPacket`, so JSON parsing and the math processing path are shared.

## Firmware compatibility
BLE service UUID: `7a1e0001-8b4f-4d2a-9c21-1234567890ab`
BLE characteristic UUID: `7a1e0002-8b4f-4d2a-9c21-1234567890ab`
Windows BLE helper looks for `XIAO-C6` or that service UUID. Android scans for the same service UUID and names `XIAO-C6` / `MR60BHA2`.
Wi-Fi sensor endpoint: `GET http://192.168.4.1/api/sensor`; AP password: `MR60setup`; AP SSID is dynamically generated by firmware as `MR60BHA2-XXXX`.

## Build/run Windows
Requirements: JDK 17, Gradle 8.x (or generate wrapper with `gradle wrapper`), Windows Bluetooth enabled for BLE.

```powershell
cd desktop
py -3 -m pip install bleak
cd ..
gradle :desktop:run
```
Choose BLE or Wi-Fi in the app. For Wi-Fi, connect the PC to the ESP32 AP first and keep `http://192.168.4.1` as the URL. The Python BLE bridge uses Windows BLE through `bleak`; Python output is used as a line-oriented notification bridge.

## Build Android
Open the folder in Android Studio (AGP 8.7.3, compile SDK 35, JDK 17). Build and install `androidApp`. BLE requires runtime Bluetooth permissions on Android 12+. Wi-Fi connection requests use Android's system dialog; type the AP SSID shown by the firmware, password `MR60setup`. The Wi-Fi polling path uses the selected `Network` directly and does not require internet access.

## Data storage
Windows DB: `%USERPROFILE%/.pulsbreath/puls_breath.db`.
Android DB: app-private `puls_breath.db`. Both save one summary row after a completed 60-second processing interval. The existing Android `DatabaseManager` was Android-only and therefore was not reused in the JavaFX source set; this project uses separate platform DB adapters with the same table/column shape. No table drop is performed.

## Important limitations / verification
- This is a source-level integrated prototype assembled from the supplied files; it has not been built on the user's machine or tested against the live radar hardware here.
- Windows BLE requires Python 3 and `bleak` (`py -3 -m pip install bleak`) and a working Windows BLE adapter. If the firmware advertises a different device name, update `NAME` in `ble_bridge.py`; service UUID is also used for discovery.
- Firmware payload must use the JSON keys `target`, `heart`, `heart_valid`, `breath`, `breath_valid`, `distance`, `distance_valid`, `recording`, `wifi_connected`, `ble_connected`.
- The mathematical thresholds are retained from the supplied processor; they are not medical diagnostic criteria. Sensor measurements must be validated experimentally.
